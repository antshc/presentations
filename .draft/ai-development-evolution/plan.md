# From Prompt Engineering to Agentic Software Factories (AI Workshop)

## Brief

| Field | Decision |
|---|---|
| Project | `ai-development-evolution` |
| Purpose | Give workshop participants a clear mental model of the four stages of AI software development, so they can place tools and practices on the path from prompts to software factories. |
| Audience | Software engineers attending an AI workshop; know the SDLC and have used AI assistants (Copilot, ChatGPT) but have not built agent workflows; slide 01 stays short, slides 05 and 07 carry the depth. *(confirmed)* |
| Duration | ~40 min (confirmed): slide 01 about 2 min, slide 05 about 7 min, the other units about 4 min. |
| Slide units | 9 (each = main screen + horizontally adjacent detail screen + a review-only reference screen with the real images; slide 01 has no detail screen, slide 08 has no reference screen) |
| Narrative | SDLC baseline → four-stage taxonomy with popularity landscape → Stage 3 workflow → Stage 4 factory → making autonomy safe (gates, proof tool, boundaries, self-improvement) → harness anatomy → shared principles → hands-on example (Matt Pocock's skills) → comic of the workshop agents (Sprinter and Mole). |
| Visual tone | draw.io **Hand-drawn** theme, clean engineering whiteboard on warm paper. |
| Branding | None. Use authentic project names/logos only where verified. |
| Accessibility | High contrast, short labels, no color-only meaning (stage name always next to the stage color), alt text for every real image. |
| Outputs | Native `.drawio` (source of truth); PNG/SVG/PDF exports to `exports/`. |

## Style decisions

- Theme: light (repository default; palette in `README.md` "Default visual profile"), used on every screen. Paper `#FAF8F2`.
- Ink and typography: charcoal `#222B35`; Kalam or Patrick Hand for headings, Inter for body labels; fall back to a legible sans-serif.
- Color roles: Stage 1–4 (slate `#64748B`, blue `#0284C7`, amber `#D97706`, green `#059669`) mark the four stages; Accent 1–4 (terracotta, stone, steel blue, ochre) mark concepts such as the harness rings; red `#EF4444` for blockers, failures and caveats only. A stage or concept keeps its color on every slide.
- Illustration and connector style: rough marker outlines and sketch arrows, one dominant drawing per main screen, connectors kept away from text, conceptual sketches for mechanisms, authentic names/logos for real projects, no stock photos.
- Project-specific overrides: hand-drawn theme instead of repository default style *(confirm against repository defaults at generation time)*. Main screen carries one message; explanations go to the detail screen or presenter notes.
- Links in this plan: never paste a bare URL or a file path. Write a Markdown link with a readable title, `[Title](url-or-relative-path)`, so the title is clickable and the address stays out of the text (local files use paths relative to `plan.md`; the full URL is kept in presenter notes where a slide needs it). The same applies to the footer notes on the slides.
- Freshly drawn assets only: the main and detail screens contain original hand-drawn sketches and editable text, never real screenshots (confirmed).
- Reference screen (third screen, horizontal, review only): each slide unit gets a third 16:9 screen to the right of the detail screen (slide 01: right of the main screen) that shows the real source images unmodified, each with a number badge "①②…" and a caption "image file → which element on the main/detail screen it was redrawn into". Its only purpose is to let the author check that the redrawn assets map correctly to the real ones. Mark it "REVIEW ONLY — remove before presenting"; place it on its own draw.io layer, hidden in exports; slide 08 has none. The same numbered badges appear small on the redrawn element so the mapping can be followed both ways.
